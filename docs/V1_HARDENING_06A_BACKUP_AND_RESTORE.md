## Ops-only tools and manifest v1

`node scripts/ops/cli.mjs --mode backup --environment disposable --fingerprint <independently-reviewed-64-hex>` is PLAN_ONLY, does not read env files or inspect/connect to Docker. `--mode restore --package <outside-package> --manifest-hash <independently-pinned-hash>` additionally needs the explicit disposable environment/fingerprint; default is integrity-checked plan only. `--mode verify --package <outside-package> --manifest-hash <trusted-hash>` is local-only integrity verification. `--mode migrations` is local source inventory. No example is an execution authorization.

Execute requires `--execute`, local operator invocation outside CI and all target proof. Backup additionally requires `--ack-quiescent`, existing external output parent, new output directory and `MEDIATRACKER_DR_ENCRYPTION_KEY` (64 hex via process env, never CLI). Restore additionally requires `--ack-trusted-backup --ack-quarantine`. Unknown/repeated flags fail closed. Production/Staging/unknown classifications are rejected, not downgraded to local. Optional `--production-fingerprint`/`--staging-fingerprint` comparisons reject equality. No URL, linked project, stored CLI credentials or local `.env` is accepted.

Proof uses the existing 05F disposable-validator: exact DB/API containers, labels, image classes and loopback API mapping. DR additionally requires a local Docker socket (inherited Docker contexts/hosts/credentials ignored), an Internal Docker network, no DB mounts/published ports/privileged/host networking, a cryptographic digest of DB container/image/network identity, and a separately provisioned `private_dr.fixture_identity` row (`singleton=true`, label `mediatracker-dr-disposable-v1`). Same database is `privacy_05f_disposable`; no provisioning/reset/drop happens here. Independent identity/fingerprint must come from operator inspection, not this script creating its own proof. The fixture being specified does not prove it exists. Changes to container identity require fresh proof.

Package manifest: `format=mediatracker-recovery`, version 1, UTC timestamp, sourceCommit, `sourceState=working-tree-source`, disposable fingerprint, tool versions, AES-256-GCM, relative artifact paths/bytes/SHA-256, ordered migration versions/LF hashes and dependency/classification records, explicit zero included Storage objects/binaries and exclusions. Database custom archive, aggregate/catalog verification and role inventory are encrypted independently with random nonces. SQL sources and non-sensitive docs are hashed. No passwords, tokens, URLs, project refs, service-role or Auth credential data. Manifest hash is returned for separate trusted retention; possession of both a tampered manifest and its newly calculated hash is not authenticity.

Integrity stops on missing file, traversal/symlink, duplicate/case-colliding path, invalid format/version/hash, zero-byte artifact, size/checksum mismatch, missing critical artifact or pinned manifest mismatch. AES-GCM rejects wrong keys/tampering. Failed packages are retained for inspection, never overwritten or labelled valid. Command status/errors are captured; raw subprocess output/error is suppressed. Buffers capped at 128 MiB and commands at 60 seconds; this is a small-fixture tool, not a scalable hosted backup agent. Windows directory/file mode bits alone do not prove ACL privacy; operator-controlled parent ACL and key custody are manual gates.

## Restore architecture and verifier

1. Verify independent target proof and package integrity; trusted backup acknowledgement before executing archived SQL.
2. Require fresh target with no application tables/views/sequences/functions; exact prerequisite role names/extensions and Auth identity hash. Managed roles, Vault and synthetic Auth are preprovisioned separately. Duplicate CREATE SCHEMA or missing view dependencies stop; never auto-clean/drop/ignore errors.
3. Restore archive pre-data → data (including actual migration ledger) → post-data (constraints/indexes/triggers/ACLs), then recreate exact `privacy_initialize_account` (Auth) and `a_privacy_storage` (Storage) trigger bindings from encrypted source definitions. Schema-scoped pg_dump alone omits triggers attached to managed schemas. Each stage is single transaction, exit-on-error, no trigger disabling, no `--no-acl`/owner weakening. Earlier sections can remain after failure or client timeout; command timeout does not prove server cancellation. Quarantine and inspect the outcome; discard/reprovision the disposable target manually rather than retrying blindly. Storage policies/metadata/binaries remain a separate manual restore gate.
4. Compare deterministic catalog/aggregate report: complete ledger; required Media/progress/profile/goals tables with RLS; private privacy lifecycle and rate-limit buckets; required barrier/limiter RPCs; columns/defaults/constraints/PK/FK, trigger/policy/function hashes, owner/ACLs, roles/extensions and row count/digests. Never treat command exit alone as success. Source fixture must be quiescent; before/after digest drift aborts backup.
5. Separately restore verified Storage binaries/metadata, reprovision Vault safely, verify actual two-owner authenticated RLS/isolation and ACTIVE/locked privacy behavior, app smoke and aggregate asset counts. These checks require future authorized disposable rehearsal, not synthetic substitutes.
6. Quarantine restored data; reconcile every completed/pending erasure and retained backup period **before** enabling login, sync, notifications, exports or assets. Never casually resurrect erased personal data. Capture a restricted recovery report with PASS/FAIL/NOT RUN for every class and measure achieved RPO/RTO.

Tool success is only `DB_RESTORE_VERIFIED`; `disasterRecovery=LIVE_UNVERIFIED` remains until manual Storage/Auth/platform/owner/smoke/privacy checks pass. Auth-last erasure is not rollback permission. Exported SQL may execute arbitrary code: verify trusted provenance and use isolated disposable resources only. No production execution mode exists in this phase; a future separately reviewed transport/protocol is required for actual hosted backup.
